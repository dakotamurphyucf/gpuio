# Tab motion implementation contract — OCH-41

Status: public API/native implementation and local validation complete; see
[evidence](../evidence/tab-motion-och41.md). Physical GPU/desktop appearance and
release acceptance remain open. The static/menu/viewport contracts remain.

The pinned styled tab bar animates Pill, Segmented and Underline indicators with
separate position/width springs, preserving velocity on interruption. Pill's newly
selected enabled text fades from normal to selected foreground with a 200 ms
cubic ease-in-out; initial layout does not fade. Selection and reveal remain
separate. Source: `component-tab-tab_bar.rs.txt` lines 179–349 and
`component-tab-tab.rs.txt` lines 688–758 in the catalog snapshots.

Public API: checked `Tab_bar.Motion.create ?spring ?color_duration ()`, with
`Motion.default`; optional `?motion` on the three Core/Bonsai tab constructors.
Omission preserves static presentation. `Animation.Spring.t` supplies finite
physical parameters and a hard settling deadline. GPUIO's default is stiffness
400, damping 40, mass 1, epsilon 0.01 logical pixels, maximum duration two seconds,
and a 200 ms text fade. These are explicit GPUIO policy values, not an assertion
that every upstream theme uses those exact spring parameters. Color duration
allows zero (immediate), rounds upward to milliseconds and is at most 60 seconds.
The gallery opts into motion and exposes its disable control.

Native behavior:

- Work with plain, decorated and structured tabs, with or without a viewport.
  Measure current option boxes, keep positions relative to the tab content origin,
  and avoid retargeting merely because the user scrolls or an ancestor moves.
- Adopt first usable geometry immediately. Retarget changed selection or geometry
  from the last painted position and velocity. Reorder follows Choice identity.
  No selection, focus, callback or scroll request is generated by motion.
- Paint one indicator beneath content, suppressing the duplicate default static
  selected fill/border. Explicit user styles retain precedence. Selected-text
  fades apply to Pill and respect explicit descendant colors.
- Reduced motion/inactive windows settle immediately. Missing selection, removed
  metadata, incompatible variants and unpainted/zero/clipped owners retire travel;
  reappearance adopts current geometry without animating from a stale hidden box.
  No frame scheduling continues after settlement, unmount or window close.
- Native state is bounded per owner and charged to admission. Coordinate snapshots
  and native row elements must not retain retired owners through frame callbacks.
  Layout may measure/preview, but only a usable native paint commits motion.
- Verify interrupted velocity, resizing/reorder/scroll, theme/style updates,
  initial/disabled/reduced/hidden behavior, resource retirement and actual native
  indicator/text paint. Keep physical GPU/VoiceOver qualification separate from
  TestPlatform evidence. A static fallback alone does not complete this feature.

The implementation appends paired internal metadata rather than altering
existing tab appearance bytes or exposing native mutable spring objects to OCaml.

Op103 `Set_tab_motion (node, config option)` carries the existing checked spring
record plus the bounded integer color duration. It is paired internal epoch-3
metadata, not a compatibility promise to an older independently built native
library. It is TabBar-only and reserves 4096 bytes for each enabled native owner;
malformed updates leave the tree/revision/accounting unchanged.

The native owner keeps two analytic trajectories and the last painted position
and velocity, a bounded selected ID, and an optional foreground epoch. The frame
holds only weak ownership and two measured boxes (first/selected). Geometry is
relative to the first box; ordinary wheel scrolling translates the scene without
retargeting. Coordinates outside the general spring property's accepted range
adopt their exact valid layout target instead of clamping it. A native paint
requests the next frame only while travel or the foreground fade is active.

Foreground uses cubic progress with linear interpolation of RGBA channels, then
ordinary native text-style inheritance. Explicit descendant colors win. Explicit
per-tab backgrounds and borders stay on their tab targets and paint above the
default traveling indicator. The indicator respects selected-target opacity,
including the existing disabled-item half-opacity. Changing theme paint does not
restart the geometry spring. Changing motion policy adopts the current target.

The owner participates in the host's full paint sweep, including windows with
only tabs. Unpainted history is cleared after deferred content finishes. Removing
metadata prunes its owner immediately on acceptance. Frame bindings hold weak
references, and there is no permanent timer or synchronous OCaml callback.
