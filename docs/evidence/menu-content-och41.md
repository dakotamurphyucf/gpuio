# Rich menu content — OCH-41

Local macOS arm64 validation, 2026-10-05, based on
`43166ab7690a9dfdf9d157952d41352663cfabb3` plus the archived source changes.
The [contract](../design/menu-content.md) adds bounded passive view content at
validated menu item paths. Registered SVGs, styled labels and native loading/
animations share existing view/resource ownership. Commands, accessibility names,
checks, eligibility, focus and navigation stay with the native row.

## Admission and native rendering

OCaml tests cover path bounds, duplicate/unknown/separator paths, rejected nested
controls, content budgets, disjoint internal/application keys and retained menu
identity across rich/plain replacement. A 602-byte transaction generated by the
public OCaml reconciler is pinned in both languages. Rust decodes and admits its
rich button, context and drawn-bar menus and verifies slot shape and context target.
Additional native tests cover nested/duplicate-command projection, malformed
slots, descendant-only invalidation, atomic rollback and platform-bar rejection.

All five production menu rendering/observation tests pass on GPUI TestPlatform.
They cover passive names/actions, navigation, one painted decorative label,
full-width selected-row paint, a running decorative spinner, no continuing frame
requests after closing its still-mounted popup, and cleanup on content removal.
Existing placement/scale, observation overflow and subscription lifecycle checks
also pass. This is native renderer evidence, not OS input or VoiceOver evidence.
Full OCaml `@runtest`, `@fmt` and the gallery build pass.
The full native/protocol Rust suite passes **1,355 tests**, with two existing
skips. Strict Clippy passes for default targets and feature-enabled test code.

## Fresh installed macOS consumer

The final independent consumer build and complete Feedback walkthrough pass
(session 42517, exit 0). Captured pixels verify green SVG artwork in a dropdown
and nested submenu, its absence after switching to plain items, and its return
when detailed items are restored. AX/keyboard checks retain original command and
section names, passive section semantics, native invocation, editor context
opening and focus restoration. Command enablement, shortcuts, palette dispatch,
notification dismissal/expiry, page remount and shutdown also pass. The owned
application process was confirmed absent afterward.

Visual inspection of the final captures confirms full-width selection paint,
visible separators and trailing submenu arrows. The public gallery exercises
icons on command and submenu labels, with a switch for plain/detailed presentation.
The renderer admits broader passive composition under the documented bounds;
these screenshots do not claim every possible custom tree or platform was tested.

Final installed binary SHA-256:
`e2f3d9b3164c28ef6df54ec3fd5a843c91b8fd058fa9a3ffb3ff268543e8d94b`.
No VoiceOver, Linux GUI, full release or physical presentation-latency acceptance
is claimed. Required hosted checks and broader OCH-41/OCH-17 acceptance remain open.

## Preserved failures and corrections

The first installed run rejected the OCaml slots: `container []` produced an
empty style declaration while native structural slots require no declarations.
Explicit `Style.empty` fixes that mismatch; the paired public transaction prevents
regression. Review also moved slots into a disjoint structural key namespace.
The next run passed icons and menu behavior but the harness queried a switch as
`AXSwitch`; the actual macOS tree and pinned adapter expose `AXCheckBox`.
The corrected query passes. Visual inspection additionally found intrinsic-width
menu rows; `w_full` restores full-row selection, separator and arrow layout.

Original fixture and test compilation failures are retained, including invalid
sparse/orphan native nodes and the erroneous assumption that plain text owns an
entry in the native entity visitation set. The final tests use observable paint,
actual animation scheduling and cleanup instead. No acceptance threshold was
relaxed and no failing run was discarded.
