# How `main.ml` drives the private foundation experiment

[README](README.md) · [Source](main.ml) · [Native boundary](native.md)
· [Private wire format](wire.md)

Foundation is a maintained research diagnostic using its own numeric-node
protocol and `Bonsai_driver`. It predates the public typed View/App contracts.
Read it to understand experiments in scheduling, lifecycle, FFI, and text
ownership; use current public APIs for new applications. Prototype integer kinds,
global refs, and manual diffs are not production contracts.

## Bonsai model and keyed computations

The local `Bonsai` module includes `Bonsai.Cont`, exposes upstream `Effect`, and
adds `state'`: a `state_machine0` whose actions are functions transforming the
current model. `change_count Int.succ` therefore uses current state rather than
a value captured by rendering. `Bonsai.state` supplies ordinary content/status
setter effects. `graph` owns these computations; `let%arr` observes reactive
values to derive output, and `and` binds dependencies rather than threads.

`component` owns count, ordered row IDs, mirrored editor content, and async
status. `Bonsai.assoc` maps stable integer keys to row graphs, each with its own
click count and optional `Edge.lifecycle` activation/deactivation effects.
Reversing order retains keyed row state; removing a key deactivates its graph.
Adding a row sequences a fresh ID thunk with a functional order update using
`Effect.bind`. `--no-lifecycle` suppresses row lifecycle registrations for a
comparison mode; it does not bypass the whole component's ownership.

The output contains an experiment `node` tree plus text/status setters. Numeric
kinds distinguish box/text/button/editor, and IDs double as click handler IDs.
Native editing owns the live buffer and edit revision. Text events mirror content
into Bonsai; Clear native text queues `Wire.Edit` with the last observed revision.
`mounted_component` uses an assoc key to mount/unmount the entire graph so shutdown
can exercise deactivation. This is not `Gpuio_bonsai.View` composition.

## Diff, acknowledgement, and display lifecycle

`flatten` converts the node tree to an integer map. `diff` compares props and
ordered child IDs, emits Upsert/Children/Remove operations, and adds Root for the
initial batch. Callback identity comparison uses handler IDs, not function
comparison. `committed` represents acknowledged state; only one `inflight` batch
is allowed. `awaiting_display` separately waits for a matching native frame.

`pump` advances a Bonsai time source from an explicit monotonic clock, flushes the
driver, computes a diff plus queued edit ops, serializes through `Wire.encode`,
and calls `Native.submit`. Empty error bytes mean admission. `Applied` checks the
expected revision and updates committed state; Frame then releases display gating
and triggers graph lifecycles. With no native diff, a logical display cycle still
refreshes committed callbacks and triggers lifecycles. Effects generated by that
cycle flush on a later tick, including the explicit 60 Hz pump fiber.

A native Click resolves a callback from committed IDs and schedules it in the
driver; stale IDs increment ignored-events. The effect changes Bonsai state,
`pump` derives/diffs output, and Rust applies the next batch. Text events carry
native edit revision and content; programmatic stale edits must be rejected.
This private path is not the public generation-safe reconciler contract.

## Eio work, native thread, and shutdown

The async button queues intent; `launch_pending` forks Eio work under the worker
switch. It updates status, sleeps 250 ms, and loads `async-message.txt` through
`Eio.Stdenv.cwd`. A self-test's second request sleeps 60 seconds and races the
host stop promise through `Eio.Fiber.first`; shutdown must cancel it before the
file read/completion. Rendering performs no file I/O.

`run` creates the wake pipe and calls `Native.init` on the main thread. The worker
runs Eio/Bonsai in an OCaml domain while `Native.run` owns GPUI on the OS thread.
Worker failure requests native quit and preserves its backtrace. After native
return, it joins the worker, calls cleanup, and raises captured failures. Worker
shutdown unmounts the graph, flushes/deactivates lifecycles, drops committed/inflight
maps, invalidates observers, and checks activation/deactivation balance.

## Exact commands and bounded claims

From the repository root using [development setup](../../docs/development.md):

```sh
GPUIO_JOBS=2 ./scripts/gpuio build examples/foundation/main.exe
GPUIO_JOBS=2 ./scripts/gpuio smoke
GPUIO_JOBS=2 ./scripts/gpuio smoke --self-test
GPUIO_JOBS=2 ./scripts/gpuio smoke --self-test --no-lifecycle
GPUIO_JOBS=2 ./scripts/gpuio smoke --two-windows
```

`smoke` builds and changes into `examples/foundation`, so the async fixture is
found. If using the built executable directly, first change into that directory
and run `../../_build/default/examples/foundation/main.exe`. Root-directory direct
launch leaves the file read pointing at the wrong location. `--hold` adds a
5-second pause late in self-test; `--two-windows` selects native-only smoke and
bypasses the Bonsai worker entirely. All modes require native graphical setup.

The self-test probes counter/keyed identity, stale handler/edit rejection,
synthetic native IME/UTF-16 behavior, real fixture read, repeated add/remove/GC,
no-diff lifecycle delivery, panic containment, malformed bytes, and cancellation.
Individual `wait_for` stages have 15-second deadlines; these are not one global
process timeout. `Native.probe` triggers diagnostic actions, not physical user
keyboard/IME input. It logs `SELF_TEST_PASS` before the final cancellation checks;
complete success also requires normal exit and `inflight_eio_cancelled=true` plus
`shutdown_complete`. Median acknowledgement latency is not frame/presentation
latency. Neither the historical experiment nor compilation establishes current
[Linux GUI acceptance](../../docs/platform-release-policy.md).
